# protein-mcp-server — Design

Protein structure & function research across **experimental (PDB)** and **predicted (AlphaFold and other 3D-Beacons providers)** structures, from one tool surface. Audience: structural-biology, drug-discovery, and bioinformatics agents.

All provider contracts below were verified against live APIs on 2026-06-15 (see [Provider Probes](#provider-probes-2026-06-15)).

## MCP Surface

### Tools

| Name | Description | Key Inputs | Annotations |
|:-----|:------------|:-----------|:------------|
| `protein_search_structures` | Search experimental + predicted structures by free text, sequence, or organism/method/resolution filters. Routes to RCSB Search v2, which indexes both the experimental PDB and computed models (`results_content_type`: `experimental` / `computational` / both) — predicted structures search through the same surface. Returns ranked, metadata-enriched hits — chain identifiers into `protein_get_structure`. Sequence hits (experimental and computed-model alike) retain the matched polymer as `entityId` while exposing the chainable entry as `id`, and carry `identity`, `evalue`, `bitscore`, and aligned ranges against the query (`queryLength` is the query's length); experimental hits carry `organisms`, a sequence hit's being the matched entity's. `organism` takes a scientific name, an NCBI common name, or a taxon ID and matches that taxon and every taxon under it; `method` takes the 13 RCSB experimental methods or an alias (`cryo-EM`, `X-ray`, `NMR`, …) and rejects anything else; `ligand` keeps entries holding an exact component ID as a bound copy. Optionally returns a **facet breakdown** (counts by method / organism / release year) alongside the hits for instant corpus orientation at no extra upstream call; facets count the filtered set, so an active organism or method filter constrains its own facet. | `query` (text), `sequence` (1-letter AA, triggers mmseqs2), `organism`, `method`, `max_resolution`, `ligand`, `content_type` (`experimental`/`predicted`/`all`), `facets` (optional dimensions to summarize), `start`, `limit` | `readOnlyHint`, `openWorldHint` |
| `protein_get_structure` | Fetch structures with metadata and coordinate-file URLs. `source` selects experimental (PDB ID), predicted (UniProt accession, isoform accession, or AlphaFold DB entry ID), or `best_available` (federated pick via 3D-Beacons for the same identifiers: the PDB entry with the widest UniProt `coverage`, else the most confident model). Surfaces confidence (pLDDT / PAE) on predicted models. Accepts IDs up to the batch cap (default 25) in one batched RCSB GraphQL call with **per-ID partial success** — IDs are trimmed and de-duplicated, resolved structures return alongside a `failed[]` list naming any IDs that missed and why (a demerged or deleted accession lists its replacements; a merged one resolves to its successor with a `notice`), and IDs past the cap return in `ignored`. All upstream lookups in a call share one time budget. Entry-endpoint records also carry polymer entities (both `authAsymIds` and `labelAsymIds`), ligands, molecular weight, and release date. Inlined coordinates arrive in 24,000-character windows: a lone selected file pages with `coords_offset` / `coordinatesNextOffset`, and an outline-on-overflow section index (each file's length) replaces them only when two or more selected files together exceed the window. `coordinateUrls` lists only files that exist: BinaryCIF from `models.rcsb.org`, no PDB format when the entry reports `pdb_format_compatible: N`, and a computed model's files from its provider (all three formats from the AlphaFold DB prediction record, best-effort — a failed lookup keeps the RCSB BinaryCIF and says so in `notice`; mmCIF from ModelArchive by entry ID). | `ids` (PDB IDs, computed-model IDs, UniProt or isoform accessions, AlphaFold DB entry IDs), `source`, `include_coords` (bool), `sections` (structures to inline), `coords_offset` | `readOnlyHint`, `openWorldHint` |
| `protein_find_similar` | Find structurally or evolutionarily related proteins. `by: sequence` → RCSB mmseqs2 sequence search over experimental PDB entries only (`protein_search_structures` with a `sequence` also reaches computed models); `by: structure` → Foldseek async search against the databases `databases` names (default `pdb100` + `afdb50`; exactly `pdb100`, `afdb50`, `afdb-swissprot`, `afdb-proteome`, `bfvd_v3`, `cath50`, `mgnify_esm30`, `gmgcl_id`, `bfmd`). Output names the engine and database it answered from; a structure hit carries Foldseek's `target` name and an `id` only where the target maps to a PDB entry or UniProt accession `protein_get_structure` resolves, and adds `chain`, `title`, `probability`, `organisms` / `taxId`, aligned spans, and a response-level `queryLength`. A sequence hit carries `identity`, `evalue`, `bitscore`, and aligned ranges, with the response-level `queryLength`. A `pdb_id` sequence query searches one protein entity — the one holding `chain` (author chain), else the lowest-numbered of at least 10 residues, never DNA or RNA — named in `queryEntityId`, with a notice listing the entry's other protein entities. `uniprot` takes a canonical or isoform accession, or a UniProtKB entry name (`HBA_HUMAN`) resolved to its entry's accession, in both modes; a merged accession answers for its successor with a notice, and a demerged or deleted one fails with its replacements. Both modes report `totalCount`/`start`/`nextStart`; a completed structure job returns its `ticketId`, so re-calling with `ticket_id` and a new `start` pages the same finished job instead of resubmitting the structure. Foldseek splits a multichain structure into one query per chain: a structure response covers one query (`query`, default 0) and reports `queryCount`; its hits are ranked by `score` across all searched databases before paging. | `by` (`sequence`/`structure`), `pdb_id` or `uniprot` or raw `sequence`, `chain`, `databases`, `query`, `ticket_id`, `max_evalue`, `min_identity`, `start`, `limit` | `readOnlyHint`, `openWorldHint` |
| `protein_track_ligands` | Ligand discovery and binding-site analysis. `mode: find_ligand` resolves a name/formula to chemical component IDs — a formula-shaped query routes to the Search API's `chemical`/`formula` terminal for an exact-composition match, anything else to the chemical-dictionary name/synonym search; candidates are re-ranked by deposition frequency within a pool of `max(limit, 25)`, and `totalCount` (RCSB's match total) beside `candidatesConsidered` (the pool) discloses — with a narrow-the-query `notice` — when the pool truncated the match set; `mode: structures_with_ligand` returns PDB entries holding a given ligand (exact `comp_id`) as a bound non-polymer copy — not a residue inside a polymer chain or a sugar inside a branched glycan — each with `title`, `method`, and `hostEntities` (the entities whose chains the depositor assigned it to; `find_ligand`'s `depositionCount` equals this mode's `totalCount` for the same component); `mode: binding_site` returns the **interacting protein residues** lining a ligand's pocket in a given structure (residue, position, chain, contact distance — via RCSB `rcsb_target_neighbors`), each in both the mmCIF label namespace (`asymId`/`seqId`) and the author namespace (`authAsymId`/`authSeqId`), plus the ligand instance's author chain and residue number; instances come in a fixed order (ligand entity number, author chain, author residue number) so `start` / `limit` pages read each once. Returns chemical metadata (formula, weight, SMILES) on resolution. | `mode`, `query` (name/formula) or `comp_id`, `pdb_id` (for `binding_site`), `start` (`structures_with_ligand`, `binding_site` instances), `limit` | `readOnlyHint`, `openWorldHint` |
| `protein_compare_structures` | Structural alignment of **2 to `PROTEIN_MAX_COMPARE_STRUCTURES` structures** (default 10, schema max 25) via the RCSB Structural Comparison service (TM-align / jFATCAT); structures past the cap return in `ignored` as `{pdb_id, chain?}`. Aligns each structure to a reference (default: the first) or computes the full `all_pairs` matrix, fanning out pairwise jobs with a concurrency cap and **per-pair partial success**. Returns TM-score, RMSD, and aligned-residue count per pair. No in-process alignment — fully edge-deployable. | `structures` (2–25, capped by config; each PDB ID + optional chain), `reference` (`first`/`all_pairs`), `method` (`tm-align`/`fatcat-rigid`/`fatcat-flexible`), `timeout_s`, `resume` | `readOnlyHint`, `openWorldHint` |
| `protein_analyze_collection` | Profile the PDB into **distributions and trends** — counts by method / organism / polymer type, resolution histograms, release-year timelines, and multidimensional cross-tabs (e.g. method × year) — over an optional scoping query; `organism` and `method` take the same forms as in `protein_search_structures` (an unknown `method` is rejected). Backed by RCSB's **server-side facet engine**: one call, compact buckets, no row pull, no SQL canvas. Fully portable (no DuckDB/Workers caveat). | `query`, `organism`, `method`, `max_resolution`, `content_type`, `group_by` (1–2 dimensions), `interval` (numeric bin width, or the date period `year` — the only one RCSB accepts; routed to whichever requested dimension can consume that value type, primary before nested child), `bucket_limit` | `readOnlyHint`, `openWorldHint` |
| `protein_get_annotations` | Sequence & functional annotation for a protein: UniProt features (domains, binding sites, PTMs, variants) + InterPro domain/family memberships (Pfam, PROSITE, …) with GO terms. Keyed by canonical UniProt accession (an isoform is rejected, naming the canonical one); resolves a PDB ID → accession via the RCSB entry's sequence cross-reference (`reference_sequence_identifiers`) when needed. A merged accession answers as its successor with a `notice`; a demerged or deleted one fails with its replacements. | `uniprot` or `pdb_id`, `chain`, `include` (`features`/`domains`/`variants`/`all`), `limit`, per-class offsets | `readOnlyHint`, `openWorldHint` |

|:-------------|:------------|:-----------|
| `pdb://{entry_id}` | Experimental structure summary (title, method, resolution, organisms, ligands, and per-entity chain IDs in both the author and mmCIF label namespaces) — injectable context twin of `protein_get_structure` for `source: experimental`. | none (single entity) |

## Overview

The headline shift from the archived v1 (experimental-only over ~230K PDB entries): predicted structures — AlphaFold's 200M+ and the wider 3D-Beacons federation — are now the larger half of the protein-structure universe. This rewrite treats experimental and predicted as **one federated surface**, with provenance always named in output. It modernizes the provider layer (Foldseek replaces the DALI-era structure-similarity path; the RCSB hosted alignment service replaces bundled in-process alignment) and adopts framework primitives that didn't exist on the old `mcp-ts-template`: a shared character budget for inlined coordinates, typed error contracts, `ctx.enrich` truncation disclosure, and confidence-aware outputs.

Corpus analytics are served by **RCSB's own server-side facet aggregation** (terms / histogram / date-histogram / multidimensional) rather than a local SQL canvas — the upstream already aggregates, so the server stays stateless and every tool is fully edge-deployable. See [Design Decision 6](#design-decisions) for why DataCanvas was evaluated and dropped.

The server is a **multi-source aggregation** server (per the design skill's boundary table): one workflow — "research a protein's structure and function" — served by six upstreams behind one tool surface. Agents never see provider names in tool names; the handler routes to the best source and the output discloses which one answered.

## Requirements

- Read-only across all providers. No writes, no auth required against upstreams (all public APIs).
- Federate experimental + predicted structures; every structure-returning result carries a `provider` / `source` field and, for predicted models, a confidence score (pLDDT) and confidence-bucket fractions.
- Two async workflows (`protein_compare_structures`, `protein_find_similar by: structure`) submit a job, poll to completion within a bounded timeout, and surface a clear "still computing / try again" path on timeout rather than blocking indefinitely. They share one async-poll helper.
- Batch structure fetches (up to `PROTEIN_MAX_BATCH_IDS`, default 25) collapse to a single RCSB GraphQL call — no N+1 — and report per-ID partial success; IDs past the cap return in `ignored`, and one 50 s budget covers every upstream lookup in a call.
- Multi-structure comparison (2 to `PROTEIN_MAX_COMPARE_STRUCTURES`, default 10) fans out pairwise alignment jobs with a concurrency cap and partial success; a slow/failed pair degrades that row, not the call.
- Coordinate and section output is bounded: a lone selected file pages in 24,000-character windows (`coords_offset`), and an outline of file lengths replaces inlined text only when two or more selected files together exceed that window.
- Corpus analytics run **server-side** (RCSB facets) — no local compute, no canvas, fully portable including Cloudflare Workers.
- No documented hard rate limits on the RCSB / EBI / Foldseek public APIs; be polite (single batched calls, internal concurrency caps on fan-out). The async services (alignment, Foldseek) are the throughput constraint, handled by submit→poll with backoff.

## Implementation Order

1. Config (`src/config/server-config.ts`) and `createApp()` wiring (identity already set: `name`/`title` = `protein-mcp-server`).
2. Services: `rcsb-service` → `alphafold-service` → `beacons-service` → `uniprot-service` → `alignment-service` → `foldseek-service` (+ shared `withAsyncPoll`). Each independently testable against its live endpoint with a sparse-payload fixture.
3. Read-only single-call tools: `protein_search_structures` (+ optional facets), `protein_track_ligands` (`find_ligand` / `structures_with_ligand` / `binding_site`), `protein_get_annotations`, `protein_analyze_collection` (facet aggregation — single RCSB POST).
4. Composed / batch tool: `protein_get_structure` (federation + per-ID partial success + windowed coordinate inlining).
5. Async workflow tools: `protein_find_similar`, `protein_compare_structures` (multi-structure pairwise fan-out).
6. Resources: `pdb://{entry_id}`, `af://{uniprot}`.

Each step is independently testable; remove the `echo.*` scaffold definitions when the first real tool lands.

## Workflow Analysis

Two tools run async / fan out; their call flows drive service-method shape, retry boundaries, and timeout handling.

**`protein_compare_structures`** — RCSB Structural Comparison, multi-structure via pairwise fan-out:

| # | Call | Purpose |
|:--|:-----|:--------|
| 0 | build pairs | `reference: first` → (s₀,s₁)…(s₀,sₙ); `all_pairs` → every combination, capped at `PROTEIN_MAX_COMPARE_STRUCTURES` |
| 1…k | `POST /api/v1/structures/submit?query=<urlencoded JSON>` per pair (Content-Type `application/json`) | Submit each pairwise job, concurrency-capped; each returns a bare UUID string |
| poll | `GET /api/v1/structures/results?uuid=<uuid>` per job | `404 "No such UUID"` (or a `200` with `info.status: RUNNING` and no `results`) = not yet ready → shared `withAsyncPoll` backs off until `PROTEIN_ASYNC_POLL_TIMEOUT_MS`. A completed job echoes its submitted pair in `results[0].structures[]` and its method in `meta.alignment_method`; a resumed pair's row takes `a`/`b` from that echo, since `modeledResidues`, `coverage`, and the TM-score (normalized by the first structure's length) are all ordered as submitted |
| merge | collect | Per-pair TM-score / RMSD / aligned-residues; pairs still computing return `status: computing`; failed pairs return `status: failed` with an `error` — partial success, never block past the budget |

Single-pair request body (verified): `{"context":{"mode":"pairwise","method":{"name":"tm-align"},"structures":[{"entry_id":"4HHB"},{"entry_id":"2HHB"}]}}`. The method schema is `additionalProperties:false` with only `name` — sending a `parameters` key (even `{}`) fails validation; `selection.asym_id` is an optional per-structure chain restriction (label_asym_id). Method names: `tm-align` / `fatcat-rigid` / `fatcat-flexible`.

**`protein_find_similar` (`by: structure`)** — Foldseek, async ticket flow:

| # | Call | Purpose |
|:--|:-----|:--------|
| 0 | resolve query to a coordinate file | PDB ID → `files.rcsb.org/download/{id}.cif` (mmCIF exists for every entry, PDB format does not; Foldseek reads both); UniProt (canonical or isoform accession, or an entry name, shape-checked first; an entry name is resolved to its accession by one UniProt request) → AlphaFold `pdbUrl`. At most 16,000,000 characters are read; a longer file fails `structure_too_large`. |
| 1 | `POST /api/ticket` (multipart: `q=@file`, `database[]`, `mode`) | Submit; returns `{ id, status }` |
| 2 | `GET /api/ticket/{id}` | Poll until `status: COMPLETE` (or budget) — same `withAsyncPoll` helper as alignment. For a new search the window starts when the call does, so steps 0–1 come out of it. Once step 1 returned a ticket, the call's 50 s budget ending during steps 2–4 also answers `status: computing` with that ticket. |
| 3 | `GET /api/result/queries/{id}/{limit}/0` | List the job's queries — one per chain of the submitted file, in file order (`job_A`, `job_B`, …). Gives `queryCount` and range-checks `query`: step 4 answers an out-of-range index with HTTP 200 and empty blocks, so the check can't be left to the provider. Read in one oversized request, since the endpoint's `limit`/`offset` paging is off by one upstream. |
| 4 | `GET /api/result/{id}/{query}` | Fetch one query's alignments: per-database blocks, each sorted by `score` descending; per-target `seqId` (a 0–100 percentage, served as a 0–1 fraction rounded to four places), `alnLength`, `prob`, `eval`, `score`, `qAln`/`dbAln`, aligned positions (`qStartPos`/`qEndPos`, `dbStartPos`/`dbEndPos`, `dbLen`), `qLen` (the query's length), and `taxId`/`taxName` on taxonomy-indexed databases (`taxId: 0` is Foldseek's placeholder for unclassified). A target header splits at its first space into the target name and a title; the database decides how the name reads. `pdb100` targets arrive as assembly files (`1crn-assembly1.cif.gz_A`): the leading four characters are the entry ID, and the label after `_` is the author chain, with a `-N` suffix on a symmetry copy. AlphaFold DB targets (`afdb50`, `afdb-swissprot`, `afdb-proteome`) follow `AF-{UniProtAccession}-F{fragment}-model_v{version}` — extract the accession to chain into `protein_get_structure` or `protein_get_annotations`. `cath50` targets are CATH domains of a PDB chain (`1cbnA00`) or of an AlphaFold model (`af_{accession}_…`); `bfvd_v3` targets name a UniProt accession that is no route to the BFVD model itself, so they carry no `id`; `mgnify_esm30`, `gmgcl_id`, and `bfmd` targets name neither a PDB entry nor an accession. The blocks are flattened and re-sorted by `score` descending (missing last, ties by database then target) before `start`/`limit` slicing — `score` is the one field comparable across databases. |

`by: sequence` is a single synchronous RCSB `service: sequence` POST — no polling. A `pdb_id` query first reads the entry's protein entities in one GraphQL call (`rcsb_entity_polymer_type` `Protein`, `auth_asym_ids` for `chain` matching); a `uniprot` query reads the sequence from UniProt, which resolves an entry name to its entry in the same request.

**`protein_get_structure` (batch + best_available)** is multi-call but synchronous: one RCSB GraphQL `entries()` call for N experimental IDs (no N+1), or per-ID AlphaFold DB (predicted) / 3D-Beacons (`best_available`) lookups, fanned out with a concurrency cap. IDs are trimmed and de-duplicated before the batch cap, and the remainder returns as `ignored`. UniProt is asked only after the model provider misses (or, under `best_available`, answers for a different accession): a merged accession resolves to its successor's model with a notice, and an inactive or unknown one fails its row. A `best_available` pick takes the PDBe entry with the widest UniProt `coverage` (`uniprot_start`/`uniprot_end` in the summary), ties to the finest resolution, confirming with a PDBe-only summary (`?provider=pdbe`) when the full one lists none; if that check fails the pick ranks the federated models alone and says so. With no PDB entry, models rank by confidence on the lDDT scale, unscored last. Unresolved IDs collect into `failed[]`, and one 50 s budget (`src/services/shared/call-budget.ts`) covers every upstream request in the call; under `predicted` and `best_available`, an ID it stops lands in `failed[]`, and so does an ID whose provider or UniProt lookup fails with any error other than a cancellation (an error status, an HTML page, a network failure, a per-request timeout), its reason saying to re-call it. When nothing resolves and no row is a missing entry (every miss an upstream failure or a budget stop), the call fails `upstream_unavailable` (retryable), so an outage or a slow upstream never reads as missing entries; when any row is a missing entry, it fails `all_failed`. A caller's cancellation still cancels the call.

**`protein_analyze_collection`** is a single RCSB Search POST with `request_options.facets` and `paginate.rows:0` — no fan-out, no row pull. The `group_by` dimensions map to RCSB facet attributes server-side (see Decision 6).

**RCSB sequence input.** Both sequence-search paths remove whitespace and uppercase only ASCII residues before validating a minimum of 10 residues in `[A-IK-Z]`. This retains B/O/U/X/Z while rejecting J and punctuation before search. Raw sequences and identifier-resolved sequences share the rule; mode guards run first, and an empty raw string retains identifier fallback.

**Annotation pages and source fidelity.** `protein_get_annotations` slices each requested class with its own zero-based `features_offset`, `variants_offset`, or `domains_offset` (default 0), keeping `limit` at 1–200/default 50. Requested classes return `featuresTotal`, `variantsTotal`, or `domainsTotal`, including zero: the first two count the entry's features and variants, and `domainsTotal` is InterPro's own membership count for the protein; omitted classes omit totals. A notice composes next offsets for remaining records and lower-offset advice for exhausted populated classes, separately from genuine absence; a merge into another accession leads it, and an InterPro walk that stops short of its count sets `truncated` and says how many memberships `domains_offset` reaches. UniProt features cover domains, binding and active sites, PTMs, topology, processing products, DNA-binding, and mutagenesis; secondary structure, isoform sequences, and sequence-record notes are excluded. An isoform accession is rejected as `invalid_accession` naming the canonical one, since UniProt annotates the canonical entry. Offsets page freshly fetched arrays, not a stable snapshot. Variant `featureId`, `originalSequence`, and `alternativeSequences` relay source presence, including empty values; missing alternatives never imply deletion. InterPro `locations[].fragments[]` retain only the requested protein's locations, with optional `start`, `end`, and `dcStatus` (from `dc-status`), preserving separate locations, gaps, order, and qualifiers in UniProt numbering.

**Optional comparison scores.** Numeric `similarity-score` and `sequence-similarity` entries are matched independently by type and relayed as optional `pairs[].similarityScore` (raw method-specific score) and `sequenceSimilarity` (0–1 fraction), including zero. Their text columns appear independently when any pair has the field; absent values remain unknown. Every metric stays attached to the job's original orientation on resume. Raw scores are not normalized across methods.

## Design Decisions

The five open decisions from `idea.md`, resolved against live probes, plus the DataCanvas evaluation (Decision 6) and the agent skill (Decision 7).

**1. 3D-Beacons as primary vs. direct RCSB + AlphaFold composition → hybrid: 3D-Beacons for the predicted/federated path, direct RCSB for the experimental search/analytics path.**

Live evidence settles this. A predicted-only accession (`A0A0C5B5G6`) returned **two models from different providers** through 3D-Beacons — AlphaFold DB (AB-INITIO) *and* AlphaFill (TEMPLATE-BASED) — that direct AlphaFold-only composition would miss entirely (the federation also fronts SWISS-MODEL, BFVD, PED, and others). So 3D-Beacons earns the **primary role for "give me models for this UniProt accession" and `best_available`**. But it is *not* a search engine: it's keyed by UniProt accession and returns a per-accession model list, with no full-text / facet / sequence search — and because it is UniProt-keyed, it can't map a PDB ID *to* an accession, so the PDB→UniProt resolve in `get_annotations` runs through the RCSB entry's `reference_sequence_identifiers`, and predicted-structure *search* runs through RCSB Search v2's `computational` content type, not Beacons. The PDB's rich query surface (full-text, mmseqs2 sequence, bound-ligand, organism/method/resolution facets) lives only in RCSB Search v2. And corpus analytics need RCSB's faceted aggregation. So RCSB stays the **direct primary for search, batch metadata, ligands, and analytics**; 3D-Beacons is the federation layer for the predicted half. Neither alone covers the workflow — the hybrid is the honest minimum. AlphaFold DB is kept as a *direct* service too (not only via Beacons) because it carries confidence detail — `globalMetricValue` (mean pLDDT), the four `fractionPlddt*` buckets, and `paeDocUrl` — that the Beacons summary abbreviates, and it backs the `af://` resource.

**2. Add the function/annotation tool now or defer → add now (`protein_get_annotations`).**

UniProt and InterPro are already required (UniProt for accession resolution and sequences, InterPro for domain context), so the marginal cost is one tool over services that must exist anyway. The probes confirm both are clean, keyless, and richly structured (UniProt `ft_domain`/`ft_binding`/`cc_function`; InterPro `{count, results[]}` with Pfam/PROSITE member DBs, GO terms, and an `in_alphafold` flag per protein). Sequence/function is the natural adjacent workflow to structure and rounds the server from "structure viewer" to "protein research." Deferring would ship services with no tool surface — wasted capability.

**3. Foldseek access — public web API vs. self-host → public web API (`search.foldseek.com`), no self-host.**

The full async ticket flow was verified end-to-end: `POST /api/ticket` (multipart structure + `database[]` + `mode`) → poll `/api/ticket/{id}` → `GET /api/result/{id}/{query}` returns complete alignments (`seqId`, `prob`, `eval`, `score`, aligned sequences, Cα coords). `/api/databases` lists the target databases the server exposes by exact name — `pdb100` (experimental), `afdb50`, `afdb-swissprot`, `afdb-proteome` (AlphaFold DB), `cath50` (CATH domains of PDB chains and AlphaFold models), `bfvd_v3` (viral), `mgnify_esm30` and `gmgcl_id` (metagenomic), and `bfmd` (complexes) — covering both experimental and predicted targets. Self-hosting Foldseek means GB-scale target databases and a compute backend — disproportionate to the workflow and incompatible with the edge target (decision 4). The public API is the right dependency; the design's only obligation is honest async handling (submit→poll→timeout) and `openWorldHint` since results depend on a live service.

**4. Edge target (Cloudflare Workers) → keep Workers as a fully supported deployment. No tool degrades.**

The alignment probe settles the original worry. The RCSB Structural Comparison service is a **hosted async REST API** (`/api/v1/structures/submit` → `/results?uuid=`), and Foldseek is likewise hosted — so `protein_compare_structures` and `protein_find_similar` need **zero in-process alignment code**. The only Workers-incompatible piece would have been DuckDB/DataCanvas — and Decision 6 removes that entirely by serving analytics through RCSB's server-side facets instead. The result: **all 7 tools are Workers-portable** (windowed coordinate inlining is streaming and slicing only; facet analytics is a stateless POST). The federated structure workflow — the headline value — is edge-native, and so is corpus analytics. No tradeoff sacrificed.

**5. Resources → ship `pdb://{entry_id}` and `af://{uniprot}`.**

Both are cheap (each is a single-entity GET already implemented for the tools), stable-URI addressable, and useful as injectable context for clients that support resources. They mirror tool-reachable data, so tool-only clients lose nothing. No `list()` — the PDB/UniProt corpora are unbounded; discovery is the search tool's job, not a resource dump. The split mirrors the federation: `pdb://` is the experimental twin, `af://` the predicted twin.

**6. Corpus analytics: RCSB server-side facets, not a DataCanvas SQL surface.**

DataCanvas was evaluated (the framework offers it) and **dropped** — it does not earn its keep here. The decision rule is *shape, not size*: a canvas earns its keep when an agent must pull row-level data and run local SQL because no server-side aggregation exists (the secedgar case — XBRL frames and 13F holdings have no aggregation API). RCSB is the inverse. Its Search v2 facet engine computes the canonical "profile the corpus" queries server-side in one call:

- **terms** — counts by category (`exptl.method`, `rcsb_entity_source_organism.ncbi_scientific_name`, polymer type)
- **histogram** — numeric distributions (`rcsb_entry_info.resolution_combined`, binned)
- **date_histogram** — timelines (`rcsb_accession_info.initial_release_date` by year/month/quarter)
- **multidimensional** — nested cross-tabs (e.g. method × year)

Probed live: a `"kinase"` query (71,772 entries) returned method counts (X-RAY 55,951 · EM 13,009 · …) and a 48-year histogram in one ~1 KB response; `"hemoglobin"` returned a 21-bin resolution histogram, 1,002 organism buckets, and a method×year cross-tab. Populating a canvas would instead require paging tens of thousands of identifiers, GraphQL-enriching every one, loading DuckDB, and re-aggregating what the facet API already returned — expensive, stateful, and Workers-incompatible, to recompute a result the upstream hands back for free. So `analyze_collection` is a thin facet wrapper: a friendly `group_by` dimension enum (`method`, `organism`, `polymer_type`, `resolution`, `release_year`, …) maps to RCSB attributes + the right aggregation type, with an optional second dimension for cross-tabs. No `query_collection`/SQL tool, no `CANVAS_PROVIDER_TYPE`. The rest of the surface was checked for a genuine canvas fit (`find_similar`, `track_ligands`, `get_annotations`) — all return bounded discovery or single-entity records, not SQL-shaped row sets. This server needs no DataCanvas.

**7. Agent guidance: one published skill, `protein-guide`.**

The gates agents get wrong cross tools: an identifier from one result going into another call (an AlphaFold entry ID, a polymer entity, a pocket residue's chain), the two chain-ID namespaces, residue numbering, and reading `best_available` picks, sequence and Foldseek hits, ligand counts, and PDB profiles. A tool description cannot carry them without bloating every `tools/list`, and they share one trigger vocabulary: passing one `protein_*` result into another call, or reporting a score, count, chain, or residue number from it. So one skill serves them all; the PDB-profiling gates are too few to earn a second. The skill is served over MCP and the server `instructions` point to it, so it reaches clients that never see the plugin or the package.

**Capability restorations (from v1, grounded on probes).** Two v1 capabilities the first-pass rewrite had dropped are restored: **binding-site residues** (`track_ligands mode: binding_site`) via RCSB GraphQL `rcsb_target_neighbors` — verified on 1IEP (imatinib → 23 residue contacts with Å distances); PDBe's old `binding_sites` REST path is decommissioned (404), so RCSB is the live source and keeps it inside `rcsb-service`. And **multi-structure comparison** (`compare_structures`, 2 to the configured cap) built as a concurrency-capped fan-out of the verified pairwise alignment job — no native multi-mode required, partial success per pair.

`async` timeouts and empty results are modeled as **success variants with a status field**, not thrown errors — the agent's next move (re-call / broaden) is data, not an exception. Batch and multi-pair tools model partial outcomes the same way: a `failed[]` / per-pair status array, never an all-or-nothing throw. This matches the framework's "server reports observable state, agent decides recovery" principle.

## Known Limitations

- **AlphaFold coverage is effectively total for UniProt.** Every well-formed accession probed (`P69905`, `P00520`, `A0A000`, `P99999`, `A8MT69`) returned a model; the only failure mode observed is a `400` on a malformed identifier. So `best_available` will almost never fall through to "no predicted model" for a real accession — the practical not-found case is a bad ID, not absent coverage. `idea.md`'s framing of "no predicted model" as a common branch overstates it; the design treats AFDB as a near-universal predicted fallback and reserves `not_found` for genuine PDB-entry misses. Where an accession UniProt lists as active has no AlphaFold DB model anyway, `af://` fails `no_model` and `protein_find_similar` `by: structure` fails `no_sequence`.
- **RCSB search returns identifiers only** — every `return_type` (`entry`, `polymer_entity`, `mol_definition`) yields `{identifier, score}` with no metadata. Every search is inherently two-step (search → Data API / GraphQL enrich). The design absorbs this inside `search_structures` (enrich the top page via one GraphQL batch) so agents see metadata-bearing hits, not bare IDs.
- **Ligand full-text is noisy.** `service: full_text` for a ligand name returns loosely-matched components (querying "imatinib" surfaced amino acids). `track_ligands` uses `service: text` on `rcsb_nonpolymer_entity_container_identifiers.nonpolymer_comp_id` with `exact_match` for structures-with-ligand (bound non-polymer copies only), and routes name→comp_id resolution through the chemical-dictionary search, not free text. Formula queries take a different terminal entirely — `service: chemical` with `parameters.type: formula` — because the `text_chem` attribute `chem_comp.formula` is not searchable upstream (`400 "search is not enabled on [ chem_comp.formula ] attribute"`), and a formula run through the name search returns components whose *names* contain formula-like tokens.
- **Binding-site residues are experimental-only.** `rcsb_target_neighbors` is computed from deposited coordinates, so `mode: binding_site` works on PDB entries, not predicted (AlphaFold) models, which have no bound ligands. The `track_ligands` description states this.
- **Pocket residues need both numbering namespaces.** `rcsb_target_neighbors` reports the mmCIF label chain and position (`target_asym_id`, `target_seq_id`) plus the author residue number (`target_auth_seq_id`), and no author chain. The label and author numbering are related by no fixed offset (1IEP label THR93 is author THR315), so `binding_site` returns both, taking `authSeqId` verbatim. The author chain comes from the entry's per-instance `polymer_entity_instances.rcsb_polymer_entity_instance_container_identifiers { asym_id auth_asym_id }` pairs in the same GraphQL call — not the entity-level `asym_ids`/`auth_asym_ids` arrays, which RCSB sorts independently (6QNR_9: `["I","OB"]` vs `["82","8E"]`, where label I is author 8E), so zipping them mislabels chains. Insertion codes are out of reach: no binding-neighbor or chain-identifier object in the Data API carries one.
- **Ligand-name candidate pools can truncate.** `find_ligand` re-ranks by deposition frequency within `max(limit, 25)` candidates. Specific names fit ("ATP": 7 matches), broad words do not ("iron": 119, "acid": 12,412). The name search offers no continuation that would make paging meaningful, so the tool reports `totalCount` against `candidatesConsidered` and tells the reader to narrow the query rather than exposing an offset.
- **Facet cardinality is capped.** Terms facets can be large (organism alone exceeds 1,000 buckets). `analyze_collection` caps buckets per dimension level (`bucket_limit`, defaulting to `PROTEIN_FACET_BUCKET_CAP`, 50) and discloses truncation as a `notice` fragment per capped position — the top-level dimension and each nested cross-tab child, since a cross-tab caps every position independently — alongside a coarse `truncated` flag. `search_structures` applies the same cap to its flat facets, with no per-call override, and its `notice` names each capped dimension and routes to `analyze_collection` with a larger `bucket_limit`; a sequence search is told to narrow the request instead, since `analyze_collection` cannot reproduce one.
- **Multi-structure compare cost scales with pairs.** `reference: first` is N−1 jobs; `all_pairs` is N·(N−1)/2. Each is an independent async alignment; wall-clock is bounded by the poll budget, and unfinished pairs return `status: computing` for re-call rather than blocking.
- **Async services have no instant results.** Alignment and Foldseek are genuinely asynchronous; a cold job is not ready on first poll (verified: a fresh alignment UUID returns `404 "No such UUID"` until computed). The bounded-poll + `status: computing` return is the contract, not a workaround.
- **3D-Beacons 404 returns `{}`** (an empty object), not an error envelope — the service layer must treat an empty/`{}` body as "no models," distinct from a transport error.
- **RCSB GraphQL entity order varies per connection.** `polymer_entities` and `nonpolymer_entities` arrive in no stable order, so `RcsbService` sorts them by entity number at each read site; anything that picks "the first" entity (the default UniProt mapping, a sequence's query entity) depends on that sort.

## Services & Resilience

Per-service backoff calibrated to upstream behavior (`withRetry` from `/utils`, retry boundary wraps fetch + parse):

| Service | Base delay | Notes |
|:--------|:-----------|:------|
| `rcsb-service` | 300–500ms | Fast, unmetered public API; retry the GraphQL/Search POST and Data GET as units. Detect HTML error pages → transient, not `SerializationError`. Facet aggregation and `rcsb_target_neighbors` are ordinary Search/GraphQL POSTs — same boundary. |
| `alphafold-service` | 300ms | Static file-backed JSON; quick. Treat `400` as a client error (don't retry). |
| `beacons-service` | 500ms | Federated aggregator, occasionally slower under fan-out. Empty `{}` body = no models (not a retryable failure). |
| `alignment-service` | poll: 1–2s backoff, capped by `PROTEIN_ASYNC_POLL_TIMEOUT_MS` | Async. Submit is fast; results poll holds `404` until computed — don't classify that 404 as terminal during the poll window. Multi-structure compare fans out pairs through `withAsyncPoll` with a concurrency cap. |
| `foldseek-service` | poll: 1–2s backoff, same budget | Async ticket. `status` field drives completion, not HTTP code. Shares `withAsyncPoll` with alignment. |
| `uniprot-service` | 300–500ms | UniProt + InterPro both fast; `400` = bad accession (client error). |

API-efficiency choices baked into service methods: batch via RCSB GraphQL `entries()` for multi-ID fetch; UniProt `fields=` selection to trim payloads; enrich only the displayed search page (not the full result set) to bound cost; corpus analytics aggregate **server-side** via facets (no row pull); internal `Promise.allSettled` with a concurrency cap on any per-accession or per-pair fan-out (`best_available` over a list, multi-structure compare).
