# 0.9.1 — 2026-11-14

## Added

- **`protein_get_structure` `all_chains`** lists every chain ID of each polymer entity; by default `authAsymIds` and `labelAsymIds` hold an entity's first 100 chains, `chainCount` gives the full count, and a notice names the capped structures ([#102](https://github.com/cyanheads/protein-mcp-server/issues/102)). `pdb://{entry_id}` still lists every chain and gains `chainCount`.
- **`protein_get_structure` accepts `pdb_id`, `id`, and `identifier`** as aliases of `ids` ([#104](https://github.com/cyanheads/protein-mcp-server/issues/104)).
- **`protein_track_ligands` `find_ligand` paging**: `start` pages blocks of `max(limit, 25)` name matches, and the output carries `start` and `nextStart`.
- **`PDBE_API_BASE_URL`** (default `https://www.ebi.ac.uk/pdbe/api`) sets the PDBe REST base used by the `best_available` PDB check.
- **2,000-hit ceiling notice** on `protein_search_structures` and `protein_find_similar` (`by: "sequence"`): a universe that returns RCSB's cap says the count is the ceiling, not a complete count.

## Changed

- **`protein_search_structures` sequence search under `content_type: "all"`** runs one RCSB query per universe and merges by `bitscore` (ties go to experimental), so each universe's hits and E-values match its own search; `totalCount` and `facets` buckets are the two universes' sums, and `score` and `evalue` compare within a universe only ([#96](https://github.com/cyanheads/protein-mcp-server/issues/96)). A universe that fails or is still searching at 35 s is left out with a notice; both failing fails the call.
- **`protein_get_structure` `best_available`** confirms a PDB entry through PDBe SIFTS `best_structures` instead of the PDBe-only 3D-Beacons summary, so P0DTC2 now picks 8CXQ rather than a SWISS-MODEL model ([#99](https://github.com/cyanheads/protein-mcp-server/issues/99)). The check is one attempt bounded at 15 s; any failure keeps the federated pick with the existing notice.
- **`protein_get_structure` `best_available` failed rows**: an ID whose PDB check failed, with no federated model to fall back on, fails as an upstream failure to re-call rather than a missing structure, so it counts toward `upstream_unavailable` (retryable) instead of `all_failed` when no ID resolves.
- **`protein_compare_structures`** runs under the 50 s call budget ([#101](https://github.com/cyanheads/protein-mcp-server/issues/101)). A pair stopped after submission returns `computing` with its uuid, one not yet submitted returns `failed` with a resubmit instruction, a failed pair keeps its uuid for `resume`, a submit that timed out is not re-sent, and a caller's cancellation rejects the call as cancelled instead of returning `failed` rows.
- **`protein_search_structures`, `protein_analyze_collection`, `protein_track_ligands` (`find_ligand`, `structures_with_ligand`, `binding_site`), and `pdb://{entry_id}`** run under the 50 s call budget; a hung request fails the call as `Timeout`.
- **UniProt merged accessions and entry names** (`protein_find_similar`, `protein_get_annotations`) cost the redirect plus one request for the named entry with the call's `fields`, where the followed redirect dropped `fields` and pulled the full entry (Q1HDT5: 2 requests, 71,985 B); a redirect without a UniProtKB `Location` fails as an upstream error ([#100](https://github.com/cyanheads/protein-mcp-server/issues/100)).
- **`protein_track_ligands` `binding_site` misses** name their case: the components the entry holds, components held without pocket contacts, a ligand deposited as a polymer chain, no current entry, or a computed model; error data gains `heldComponents` and `polymerLigands` ([#105](https://github.com/cyanheads/protein-mcp-server/issues/105)). Contacts are described as polymer residues, since DNA and RNA entries have them too.
- **`protein_track_ligands` `structures_with_ligand` zero-hit notice** separates an ID the Chemical Component Dictionary lacks from a real component with no bound copy.
- **Facet-cap notices** on `protein_search_structures` and `protein_analyze_collection` tell callers at the 500-bucket cap to narrow the request instead of raising `bucket_limit`.
- **Framework files** synced to `@cyanheads/mcp-ts-core` ^0.13.22; `.env.example` lists `MCP_JWT_EXPECTED_AUDIENCE` and `MCP_JWT_EXPECTED_ISSUER`.

## Fixed

- **`protein_find_similar` ticket recipes** name the required `by: "structure"` and, for re-paging, `start` and `limit`, so a replayed recipe is accepted; the `protein_compare_structures` resume recipe likewise names `structures`, `reference`, and `method`.
- **A caller cancelling a `protein_find_similar` structure search** surfaces as cancelled (-32011) instead of `search_failed`.
- **`protein_find_similar` `query_out_of_range`** renders the Foldseek ticket as a code span in `content[]`.
- **`protein_track_ligands` `binding_site`** trims `pdb_id`, and a whitespace-only ID is a missing parameter.
