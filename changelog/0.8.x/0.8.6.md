# 0.8.6 — 2026-10-07

## Changed

- **Framework `@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.13** — tool error results carry `data.requestId` and end with `request <id>` (0.13.10); declared recovery hints are filled by the framework, hint text unchanged (0.13.10); a JSON-stringified object or an integer sent for a string field is repaired before validation (0.13.9); stack traces, request context, and `rootCause` no longer reach error `data` (0.13.7, 0.13.8, 0.13.13); MCP SDK `@modelcontextprotocol/server` ^2.0.0 → ^2.2.0 (0.13.9, 0.13.11).
- **Tool error recovery forwards** — the `ctx.recoveryFor(...)` arguments are gone from every `ctx.fail` call in the seven tool definitions, because the framework now attaches the declared hint itself. The recovery hints shipped before 0.8.6 too; what callers see is unchanged except for the added request ID.
- **Dockerfile** (0.13.10, 0.13.11) — production dependencies install in a `deps` stage on the build platform, cross-installing for the target architecture, so multi-arch builds no longer run Bun under QEMU. Musl-only packages are pruned from the glibc image, the production stage no longer carries `bunfig.toml` or an install step, and the unread `ENV MCP_FORCE_CONSOLE_LOGGING` is gone. Bun base images 1.4.0 → 1.4.2.
- **`server.json`** (0.13.11) — npm entries drop the `run start:*` arguments a registry client would hand the bin and set `runtimeHint: "npx"`; the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` `value: "http"`, so a registry client launching it gets the HTTP transport.
- **Packaging and docs** — `.env.example` documents the newer framework variables; `.env*` ignore rules, `!dist/*.mcpb` in `files`, and `/.cache/` and `/logs/` in `.mcpbignore` follow the 0.13.11 scaffold; the README tool and resource sections are condensed.
- **Framework skills and scripts** resynced; `.github/workflows/codeql.yml` updated to the template's per-language jobs.
